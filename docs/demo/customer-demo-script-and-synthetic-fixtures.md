# Trace QMS — customer demonstration script and synthetic content plan

**Planning-only materials.** No tenant, users, documents, or live database records are created by this file. All names and records below are fictional.

## Demonstration objective (15 minutes)

Show a prospective laboratory customer how Trace QMS supports controlled documents, review and approval, revision traceability, role-based access, and audit evidence. Demonstrate only capabilities verified in the deployed build; if a feature is not enabled, describe it as planned rather than working.

| Time | Demonstration | Expected evidence |
| --- | --- | --- |
| 0–2 min | Introduce the synthetic Trace Demo Laboratory and role-based navigation | Demo banner; synthetic organization; clearly fictional users |
| 2–5 min | Locate and open a controlled SOP; inspect revision, status and effective date | Document metadata and revision history |
| 5–8 min | Demonstrate a draft revision and route for review | Workflow steps, assigned reviewer and controlled status transitions |
| 8–10 min | Show reviewer/approver permissions and approval evidence | Role-specific actions and timestamped events; no shared credentials |
| 10–12 min | Demonstrate publication and acknowledgment/training **only if supported** | Approved document, effective revision, user acknowledgment evidence, or a rehearsed training certificate |
| 12–14 min | View audit history and demonstrate access isolation | Event actor, action, time, record; no cross-tenant records |
| 14–15 min | Questions and implementation discussion | Customer needs and next steps |

## Proposed workflow scenario

1. Quality Manager opens SOP-QC-002 v1.0 and creates a draft revision v1.1.
2. Reviewer checks the draft and records comments or requested changes.
3. Quality Manager resolves comments and routes the final revision for approval.
4. Approver signs or approves using the deployed application's supported mechanism; do not claim Part 11 compliance without independent validation.
5. Published revision becomes visible to authorized readers, with history preserved.
6. Auditor views corresponding audit events and confirms an ordinary reader cannot edit or approve.

**No fabricated audit entries:** audit evidence must be generated by actual demo interactions once separately authorized.

## Training certificate demonstration

Rehearse this workflow in the approved demo tenant before a customer session. Use a fictional employee linked to an active demo learner account, a training manager in the same tenant, and an active demonstration course. Prepare one recorded completion in advance so the customer session can start with the certificate.

To set up the learner, open **Administration → Users & access → Training employee links**. An organization-wide administrator with training management and personnel read access can select the active demo account and employee, review the pair, and confirm the link. The link is audited and gives the learner access to their own training history. In **Saved training employee links**, check that the row pairs the intended account with the intended employee and that both status columns show `ACTIVE`.

1. In **Training management**, assign the course to the fictional employee. If the assignment uses a published course version, sign in as the learner and pass its recorded assessment in **My Training** before the manager records completion.
2. In **Training management → Record completion**, enter a completion date and result for that assignment. The completion date must follow the assignment and any required passing assessment. For courses coded `DEMO-HIPAA` or `DEMO-BBP`, attach a synthetic governed evidence file in `AVAILABLE` status. Practice quiz scores alone cannot create an official completion.
3. Sign in as the linked learner. In **My Training → Official training completion history**, select **Print certificate** on the sample completion.
4. Select **Print or save as PDF**. Verify that the preview shows the fictional employee, course title and code, date, result, and record reference. Confirm that the print button is absent from the output. Save a sample PDF only if needed for the walkthrough.

Keep the exercise in the demo tenant. Verify the completion in Trace QMS using its record reference before presenting the certificate.
