# Controlled User Manual Launch Baseline

## Controlled identity

The authoritative product manual is reserved as:

- Document code: `UM-QMS-001`
- Name: **Trace QMS Controlled User Manual**
- Owner: Trace Scientific product/QMS governance
- Release model: existing `UserManualRelease` controlled release architecture

This slice does not publish a manual release. It establishes the launch baseline and an administrative readiness view so content can be authored, reviewed, frozen into a release, and published through the existing governed lifecycle.

## Required launch sections

1. Document control and manual governance
2. Access, authentication, and user responsibilities
3. Navigation and contextual Help
4. Document operations and controlled files
5. Review queues and approval assignments
6. Records management
7. Personnel, credentials, and qualifications
8. Training and competency
9. Quality events
10. Laboratory operations
11. Reporting and analytics
12. Administration and configuration
13. Notifications
14. Help, customer support, and controlled support access
15. Evidence handling, integrity, and prohibited content
16. Glossary and status definitions

## Release rule

Manual content is not authoritative merely because a section revision exists. A controlled release must snapshot explicit section-revision IDs, be published by an authorized platform Help manager, and reach its configured effective date before ordinary authenticated users can see it.

The first release should be versioned only after the content is reviewed against the actual launch build. Software changes that materially affect operating instructions require a new manual section revision and a new controlled release.

## Separation

The product manual is platform documentation. It does not grant tenant permissions, replace tenant SOPs, create signatures or approvals, or modify regulated tenant records.
